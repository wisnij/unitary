# Design: screen-reader

## Context

The semantic-labels change gave static freeform controls accessible labels, but dynamic content is still silent or ambiguous for assistive technology (AT):

- `ResultDisplay` (`lib/features/freeform/presentation/widgets/result_display.dart`) renders each `EvaluationResult` variant visually; updates are never announced.  The error variant's `Icon(Icons.error_outline)` has no `semanticLabel`, so a screen reader reads the message with no indication it is an error.
- Worksheet cell errors (`lib/features/worksheet/presentation/worksheet_screen.dart`) are signaled only by red text *inside* the value `TextField` — a screen reader reads the error string as if it were the field's content, and sighted users get a color-only signal (WCAG 1.4.1).
- The idle-example hint is a bare `GestureDetector` with no button role; the long-press-to-copy gestures (worksheet value cells, About screen rows, unit detail definition) are undiscoverable through AT.

Established conventions apply throughout (per project preference): WCAG 4.1.3 status messages → polite live region; native `errorText` semantics for field errors; `CustomSemanticsAction` for auxiliary gestures.

Result strings are generated by `lib/shared/utils/quantity_formatter.dart`; scientific/engineering exponents are emitted by our own code as `e+N`/`e-N` (and Dart's `toStringAsPrecision` in automatic notation also emits the signed `e+N` form), so spoken-exponent rewriting needs no lexer support.

`WorksheetRowWidget` (`worksheet_row_widget.dart`) is orphaned — `WorksheetScreen` builds table rows inline; only the widget's own test references it.  This change modifies `worksheet_screen.dart` and leaves the orphan untouched.

## Goals / Non-Goals

**Goals:**

- Announce every settled freeform evaluation result (including errors) via a polite live region, in a speech-friendly form, unconditionally in both evaluation modes.
- Expose worksheet cell errors through native `errorText` semantics with a visible non-color indicator.
- Make the idle-example tap target and all long-press copy gestures discoverable through AT.
- Coverage-style tests so new `EvaluationResult` variants cannot ship without a spoken form.

**Non-Goals:**

- Unit-name expansion in speech ("kg" → "kilograms") — deferred as a possible later series of small enhancements.
- `^2` → "squared" / `^3` → "cubed" special-casing — same deferral.
- Per-row worksheet error *announcements* — deferred until user-editable worksheets (Phase 12); predefined templates cannot produce row-level dimension mismatches.
- Labeling the worksheet *label-cell* long-press (transfer active row's value into this row) — its spoken description needs design thought and it is most useful alongside editable worksheets; revisit in Phase 12.
- Any visual or behavioral change for non-AT users, except the worksheet error display change.

## Decisions

### D1: Polite live region on `ResultDisplay`, unconditional

Wrap the result container in `Semantics(liveRegion: true, label: <spoken form>)`.  The label changes whenever the evaluation state changes, which triggers a polite announcement (queued behind current speech, no focus move) — the WCAG 4.1.3 convention.

- In on-submit mode this *is* announce-on-submit: the label only changes when the user submits.
- In real-time mode it announces on debounce-settle, the standard behavior for live results.  Intermediate errors while typing are accepted; on-submit mode is the escape hatch for users who find it chatty.

**Alternative rejected:** announce-only-on-Enter regardless of eval mode.  A live region cannot express this (in real-time mode the label has already changed before Enter), and the imperative `SemanticsService.announce()` is deprecated on Android.  Plumbing an announce-trigger flag through the provider was judged real complexity for a mode AT users are unlikely to use.

The visible child widgets are wrapped in `ExcludeSemantics` (same pattern as the operator keys) so the spoken label is not double-read alongside the raw text nodes.  A browsing user focusing the result box hears the same spoken-form label.

### D2: Spoken form built by string rewriting of formatter output

A `formatSpeech(String)` utility in `lib/shared/utils/quantity_formatter.dart` rewrites an already-formatted display string into its spoken form:

- `=` → "equals", `/` → "per", `^` → "to the power", `×` → "times"
- exponent suffix `e+N` / `e-N` (digit followed by `e`, sign, digits — exactly the form our formatters emit) → " times 10 to the [negative] N"

A presentation-layer helper (e.g. `resultSpeechLabel(EvaluationResult)` next to `ResultDisplay`) does an **exhaustive switch** over the sealed `EvaluationResult`, composing each variant's spoken label from its existing display strings via `formatSpeech`, joining multi-line variants (e.g. conversion + reciprocal line) with sentence breaks, and prefixing `EvaluationError` with "Error: ".  Idle announces the instruction/example text.

**Alternative rejected:** rebuilding speech from structured `Quantity` data in the provider.  The state variants store pre-formatted strings assembled with display-specific logic (output-unit disambiguation, `replaceFirst('= ', '')` adjustments, reciprocal lines); regenerating them in parallel would duplicate that logic and drift.  String rewriting is safe because we own the string grammar: our formatters always emit the signed `e+N` form, so the exponent regex cannot misfire, and symbol wording matches the operator-key label map's spirit.  (A user-typed output unit like `2e+3 m` would also be rewritten — into a *correct* spoken form, so this is harmless.)

### D3: Worksheet cell errors via `InputDecoration.errorText`

When `WorksheetCellResult.isError`, the cell's `TextField` gets `errorText: <error string>` and an **empty field value**, replacing today's red-styled error text inside the field.  This buys, for free: native error semantics (screen reader announces the field as invalid with the error message), a visible non-color indicator (message line below the field), and removal of the "error string pretends to be field content" confusion.

Layout note: `errorText` adds a helper-text line, growing that `TableRow`'s height.  `Table` handles per-row heights; the label cell shares the row, so verify vertical alignment visually and in widget tests.  The red text `style` override on the field becomes unnecessary and is removed.

### D4: `CustomSemanticsAction` on copy gestures; `button: true` on the idle example

Each long-press-to-copy `GestureDetector` gains `Semantics(customSemanticsActions: {CustomSemanticsAction(label: 'Copy value'): <same callback>})` (label adjusted per site, e.g. "Copy version").  Sites: worksheet value cells, About screen rows, unit detail definition.  TalkBack surfaces these in the actions menu, VoiceOver in the rotor; the raw long-press action `GestureDetector` already exposes keeps working.  The confirmation `SnackBar`s are announced by Flutter automatically.

The idle-example tap target gains `button: true` semantics (plus the existing tap action), so AT reports it as actionable.

### D5: Tests follow the semantic-labels coverage pattern

- `formatSpeech` unit tests: symbol map, exponent forms (positive/negative, automatic/scientific/engineering outputs), strings with no rewritable content.
- `resultSpeechLabel`: exhaustive-switch compile guard (adding an `EvaluationResult` variant breaks the build) plus per-variant label assertions, including the "Error: " prefix.
- Widget tests via `tester.getSemantics`: `ResultDisplay` node has `liveRegion` set and the expected label per state; erroring worksheet cell exposes error semantics/`errorText`; idle example exposes button; each copy site exposes its labeled custom action.

## Risks / Trade-offs

- [Live-region behavior differs between TalkBack and VoiceOver; iOS handling is less standardized] → Android is the primary target; add an on-device TalkBack pass to the task list, VoiceOver deferred with iOS support generally.
- [Real-time mode announces intermediate errors mid-typing] → accepted per convention; polite queueing plus the 500 ms debounce bounds the noise, and on-submit mode exists.
- [`errorText` changes worksheet row height when errors appear/disappear] → visual verification task; predefined templates rarely error, so churn is minimal in practice.
- [`ExcludeSemantics` over the result hides individual text nodes from AT browsing] → intentional; the composed label carries the same content.  The result text was never selectable, so nothing is lost.
- [String-level speech rewrite could mis-render exotic user-typed output units] → the rewrite only touches our five symbols and the signed-exponent pattern; worst case is slightly stilted but semantically correct speech.
